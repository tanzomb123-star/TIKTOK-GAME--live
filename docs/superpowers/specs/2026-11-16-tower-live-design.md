# Tower Live: เอกสารออกแบบ (ฉบับร่าง รออนุมัติ)

วันที่: 2026-11-16

## 1. เจตนาและเหตุผล
เกม Tower Defense ที่ผู้ชม TikTok Live เล่นร่วมกันผ่านคอมเมนต์ ไลก์ และของขวัญ เพื่อปกป้อง "บ้านสตรีมเมอร์" จากศัตรูเป็นเวฟ
เป้าหมายหลัก: ให้ได้ของที่เล่นได้เร็วที่สุด เพื่อทดลองไลฟ์จริง
เหตุผลที่เลือกแนวนี้: ผู้ชมร่วมมือกันสู้ จึงรองรับคนจำนวนมากได้ และของขวัญมีผลชัดเจนต่อเกม
(เหตุผลเชิงธุรกิจของผู้ใช้ เช่น ไลฟ์เองหรือขายต่อ ยังไม่ได้ระบุ ผู้ใช้ไลฟ์จาก TikTok บนคอมพิวเตอร์)

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / สิ่งที่ถือว่าล้มเหลว
**เป้าหมาย**
- เล่นได้ครบรอบ 10 เวฟ ใช้เวลา 5-8 นาทีต่อรอบ
- ผู้ชมใหม่เข้าใจวิธีเล่นภายใน 10 วินาที (มีคำอธิบายบนจอ)
- ปรับสมดุลได้จากไฟล์ `config.js` ไฟล์เดียว
- ทดสอบได้โดยไม่ต้องไลฟ์ (ตัวจำลองคอมเมนต์)

**ไม่ใช่เป้าหมายใน MVP**
- ระบบบัญชีผู้เล่น คะแนนถาวร หรือฐานข้อมูล
- เกมบนมือถือ หรือหลายแพลตฟอร์มไลฟ์
- ภาพและเสียงที่ขัดเกลาแล้ว (ใช้ของสำเร็จรูปก่อน)

**ถือว่าล้มเหลวแม้ทำงานได้**
- ผู้ชมต้องอ่านนานก่อนเล่นได้
- ของขวัญที่ส่งแล้วไม่เห็นผลบนจอทันที

## 3. ข้อจำกัด
- ไลฟ์จาก TikTok บนคอม จับภาพเกมด้วย OBS หรือ TikTok LIVE Studio
- ตัวเชื่อมใช้ TikTok-Live-Connector (ไลบรารีของชุมชน ไม่เป็นทางการ) อาจพังเมื่อ TikTok เปลี่ยนระบบ และอาจขัดข้อกำหนดของแพลตฟอร์ม ผู้ใช้ต้องรับความเสี่ยงนี้เอง
- สิ่งที่ตัวเชื่อมให้มา: คอมเมนต์ ไลก์ ของขวัญ การเข้าห้อง ต้องตรวจจริงตอนทดสอบว่าข้อมูลครบแค่ไหน
- ต้องมี Node.js บนเครื่องที่ใช้ไลฟ์

## 4. วิธีทำที่พิจารณา
| แบบ | ข้อดี | ข้อเสีย | ผล |
|---|---|---|---|
| **A. เว็บเกม Phaser 3 + Node.js ตัวเชื่อม** | เร็วที่สุด ทดสอบง่าย ภาพ 2D พอ | ตัวเชื่อมไม่เป็นทางการ | **ผู้ใช้เลือก** |
| B. Godot/Unity | ภาพสวยกว่า | ช้ากว่าราว 2 เท่า | เก็บไว้ทีหลัง |
| C. TikTok LIVE Games ทางการ | เสถียร ถูกต้อง | ต้องสมัครและรออนุมัติ | ไม่ใช่ทางลัด |

ตรรกะเกมเขียนแยกจากตัวเชื่อม เพื่อย้ายไป B หรือ C ได้ภายหลัง

## 5. กติกาเกมตั้งต้น (เป็นข้อเสนอของผม แก้ได้)
- มุมมองด้านข้าง บ้านอยู่ซ้าย ศัตรูเดินมาจากขวา
- ชนะเมื่อรอดครบ 10 เวฟ แพ้เมื่อ HP บ้านหมด
- คอมเมนต์ `1` / `2` / `3` = เรียกทหาร 3 แบบ (ใช้พลังงาน)
- ไลก์ = เติมพลังงานรวมของทุกคน
- ของขวัญเล็ก = อัปเกรดหอคอย / กลาง = สกิลล้างจอ / ใหญ่ = เรียกบอสช่วย (จับคู่ตามมูลค่าเหรียญใน `config.js`)
- ผู้ชมที่ช่วยมากที่สุดขึ้นอันดับ "ผู้ช่วยเด่น" บนจอ

## 6. โครงสร้าง
```
tower-live/
├── server/
│   ├── index.js     # รับ event จาก TikTok → ส่ง WebSocket
│   └── mock.js      # จำลองคอมเมนต์/ไลก์/ของขวัญ
├── game/            # Phaser 3
│   ├── scenes/      # Boot, Play, GameOver
│   ├── systems/     # waves, units, towers, events
│   └── config.js    # คำสั่ง/ของขวัญ → ผลในเกม
├── overlay/         # เวฟ, HP บ้าน, อันดับ, คำอธิบายวิธีเล่น
└── docs/
```
เทคโนโลยี (เป็นการตัดสินใจของผม): Node.js, Phaser 3, `ws`, `tiktok-live-connector`, Vite สำหรับรันเกมเว็บ

## 7. แผน 5 วัน
| วัน | งาน | เสร็จเมื่อ |
|---|---|---|
| 1 | ตั้งโปรเจกต์ ฉากเดียว บ้าน ทางเดิน ศัตรู 1 แบบ | ศัตรูเดินมาโจมตีบ้านได้ |
| 2 | ระบบเวฟ ทหาร 3 ชนิด ตัวจำลองคีย์บอร์ด/mock | เล่นเองได้ครบ 10 เวฟ |
| 3 | ต่อ TikTok-Live-Connector ส่ง event เข้าเกม | ผู้ชมจริงสั่งได้ |
| 4 | ของขวัญ 3 ระดับ อันดับผู้ช่วยเด่น | เห็นผลของขวัญบนจอทันที |
| 5 | ไลฟ์ทดสอบสั้น ปรับความยาก เสียง เอฟเฟกต์ | พร้อมเปิดไลฟ์ |

## 8. ปล่อยให้ผู้สร้างตัดสินใจเอง
ขนาดหน้าจอ ค่าตัวเลขสมดุล ชื่อทหาร สีสัน และรูปแบบ overlay

## 9. ความเสี่ยง
- ตัวเชื่อมไม่เสถียร: เตรียมโหมด mock และบันทึก event ไว้เล่นซ้ำ
- ผู้ชมน้อย: ไลก์ไม่พอเติมพลังงาน ให้มีพลังงานเกิดเองช้า ๆ เป็นพื้นฐาน
- ผู้ชมสแปมคอมเมนต์: จำกัดจำนวนคำสั่งต่อคนต่อวินาที
